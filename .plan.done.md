# План: фиксация числа колонок (скользящее окно) — итерация 3

## Цель (спецификация пользователя)
Замок фиксирует ЧИСЛО видимых колонок:
- клик по папке в последней колонке НЕ создаёт новую колонку — окно сдвигается
  вправо ([Vault][Проекты][Идеи] + клик Sub → [Проекты][Идеи][Sub]);
- клик по любой колонке левее последней снимает фиксацию;
- состояние переживает перезапуск.
Заменяет вариант «папка как временный корень» (lockedFolderPath, a79b005).

## Ключевая идея
selection[] и вся навигация не меняются. Меняется только окно рендера:
показываем последние N колонок цепочки. N берём в момент нажатия замка.

## Шаги
1. [x] settings.ts: `lockedFolderPath: string | null` → `lockedColumnCount: number | null`.
2. [x] pure.ts: `lockStartDepth(folderColumns, lockedCount)` =
   max(0, folderColumns − max(1, lockedCount)). Тесты переписаны (5 кейсов).
3. [x] view.ts:
   - `folderColumnCount()`: число папочных колонок текущей цепочки (root включён);
   - кнопка: lock → count = folderColumnCount(), unlock → null;
   - render(): startDepth = lockStartDepth(...), колонки с depth < startDepth скрыты;
   - selectItem(): если locked и depth < folderColumnCount()−1 (клик левее
     последней колонки) → unlock;
   - remap/prune для lockedFolderPath удалены (count не привязан к пути).
4. [x] i18n: «Зафиксировать число колонок» / «Снять фиксацию колонок» (en+ru).
5. [x] npm test (35 passed) + build + eslint src (0 ошибок).
6. [ ] Коммит в dev, установка в vault Raincoat, ручная проверка.

## Поведение по краям
- ArrowLeft / крошки (навигация влево): окно скользит влево, замок остаётся.
- Цепочка короче N: показываются все колонки, замок остаётся.
- Замок в единственной колонке (корень): N=1 → навигация в одной колонке.
- Удаление/переименование папок: selection чинится существующей логикой,
  окно пересчитывается — сбрасывать нечего.
- Старые ключи panelLocked / lockedFolderPath в data.json игнорируются.
- Колонка превью (showPreview) в счёт N не входит.

# План: ширина каждой колонки мышкой + фикс невидимого resize

## Root cause
CSS колонок: `flex: 1 0 var(...)` + `max-width: 280px`. С авто-панелью
flex-grow съедает сужение (ноль визуального эффекта), расширение
упирается в 280px. Ручка «не работает».

## Решение
Колонки фиксированной ширины (без grow): своя ширина или дефолт.
Ручка на правом крае меняет ширину ИМЕННО этой колонки (по пути папки),
панель при авто-режиме подстраивается живьём во время драга.
Двойной клик по ручке — сброс к дефолту.

## Шаги
1. [x] tests: desiredPanelWidth(contentWidth, windowWidth, minWidth) —
   переписать 3 кейса (RED).
2. [x] pure.ts: новая сигнатура — сумма ширин вместо count×width (GREEN).
3. [x] settings.ts: `columnWidths: Record<string, number>` (путь → px),
   слайдер = ширина по умолчанию (переименовать строки).
4. [x] view.ts: autoResizePanel публичный, ширина = сумма offsetWidth
   колонок; remap/prune columnWidths при переименовании/удалении.
5. [x] column.ts: override --ce-col-width на конкретной колонке;
   ручка: live-ширина колонки + live-панель, mouseup сохраняет,
   dblclick сбрасывает.
6. [x] styles.css: `flex: 0 0 var(--ce-col-width)`, убрать max-width 280
   (бонус: слайдер >280 начинает работать), мобильный блок поправить.
7. [x] npm test + build + eslint src → 0 ошибок.
8. [x] Коммит в dev, копия в vault Raincoat.

## dnd файлов
Регрессии в коде не нашёл (dnd.ts не менялся, drop-путь цел).
Ждём от пользователя точный симптом: не тащится / нет подсветки цели /
бросил и ничего не переместилось. Возможно жалоба была про ручку.
